# Обзор литературы

Поиск 21.09.2026 шел параллельно по шести областям. Статьи читались в основном на уровне аннотации, часть на уровне метода; полные тексты почти не читались, поэтому цифры ниже это цифры авторов, пересказанные по аннотациям. Каждый arXiv-идентификатор в этом файле проверен 21.09.2026 по странице arXiv: название и дата совпадают, выдуманных ссылок нет. Лицензии моделей и датасетов проверены через API Hugging Face и GitHub.

Колонка «Прочитано» говорит, сколько реально прочитано: А = аннотация, М = аннотация и метод, К = только карточка модели или датасета.

## 0. Что литература говорит в целом

Пять выводов, на которые опирается план. Каждый подтверждён несколькими независимыми работами.

1. **LLM-судьи слабы ровно на наших трудных случаях.** Судья, получивший всю траекторию τ²-bench, не превышает AUROC 0.65 на «ложном успехе» (2606.09863). Лучшая из 13 моделей находит шаг с галлюцинацией в инструменте в 11.6% случаев (2601.06818). Согласие одиночного судьи с людьми κ 0.57 против 0.84 между людьми (2604.16706). На длинном контексте судьи начинают перестраховываться и помечать лишнее (2604.07223), а сама длина контекста снижает точность на 14-85% даже при идеальном поиске (2510.05381). Это объясняет форму таблицы лидеров: precision 0.25-0.55 у большинства команд.
2. **Детерминированные проверки на τ²-bench дают высокую точность, но не все.** Проверка допустимости отмены в airline: 100% precision на 161 срабатывании; «прочитал перед записью»: 78%; проверка багажа: 5% (2607.07405). Правила, сгенерированные LLM без ревью, проходят 75-82% тестов (2507.16459). Вывод: правила писать и проверять руками, по одному, с замером точности.
3. **Размеченные траектории τ²-bench существуют.** AgentProcessBench (250 траекторий τ², пошаговая разметка людьми, MIT), TrajErrBench (400 неудачных траекторий airline и retail с отмеченным первым решающим шагом ошибки), публичный бакет лидерборда τ²-bench с тысячами траекторий и наградами. Это снимает главное ограничение проекта, 46 размеченных примеров, по крайней мере для калибровки.
4. **Узкий вопрос лучше общего.** Верификатор, который проверяет конкретный вызов по чек-листу, выведенному из политики, с правилом «доверять результатам инструментов, а не словам пользователя», находит нарушения с меньшим числом ложных блокировок, чем проверки аргументов (2606.29225). Обратная сторона: вопрос «есть ли тут галлюцинация» на всём транскрипте работает плохо (пункт 1).
5. **Порог решает не меньше модели.** Для откалиброванных вероятностей оптимальный по F1 порог равен половине достижимого F1 (1402.1892). Наш размеченный файл 50 на 50, тест 23.7%: вероятности нужно пересчитывать под долю класса, иначе модель переоценит число единиц.

**Предупреждение о бакете лидерборда.** Идентификаторы наших примеров (`airline__21::t7`) и имена файлов бакета (`4trials`) наводили на мысль, что организаторы строили данные из этих траекторий. Проверено 21.09.2026 (`results/source_match.json`): для airline, retail и telecom это не так, длинные последовательности вызовов наших примеров с бакетом расходятся. Текст ниже оставлен как исходная формулировка риска. Если это так, в бакете могут лежать ровно те диалоги, из которых сделан тест. Обучение на них формально не запрещено правилами, но близко к работе с тестовыми входами, и лицензия данных не указана. Решение: траектории используются для валидации и слабых меток, в архив решения не попадают (DECISIONS, решение 13).

Собственный вывод, не опубликованный результат, но полезный для плана: каждый сабмит раскрывает точные счётчики на публичном тесте. Recall = TP / 130 даёт TP, precision даёт число предсказанных единиц k. Если новая версия только добавляет срабатывания к старой, разность ΔTP / (ΔTP + ΔFP) это точность добавленных правил на реальных данных.
